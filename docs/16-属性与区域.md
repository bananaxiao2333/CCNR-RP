# P16 玩家属性 + 区域（拓展设定）（docs/16）

> 对应 issue #2「增加玩家属性编辑器」与 issue #3「特殊按钮」的落地部分。
> 一句话：**阵营属性是数据、区域是数据，本 mod 只发布事实与判定，功能本体（含核弹）在外部。**

## 1. 需求与边界

- **issue #2**：能在管理界面按阵营编辑该阵营玩家的属性（如血量），出门是满状态；需适配 FirstAid。
  维护者定调：**先原版属性，再扩展 mod；必须解耦**（不能重演 better_looting / corpse 那类兼容事故）。
- **issue #3**：需要在阵营管理界面增加"是否可以启动弹头"；维护者定调：**核弹功能非本 mod 内容**，
  相关功能移去"拓展设定面板选区域"；安全/突袭的"类原版按钮触发机制"**暂不采纳**（等对局状态机完善）。
- 本仓库的交付边界：
  1. 阵营属性配置（原版属性 + 任意 mod 属性，按注册名寻址）+ 管理面板编辑器 + 命令 + FirstAid 适配；
  2. 区域（目标区）定义与判定 + 阵营弹头许可/目标区域 + 管理面板「拓展设定」页签 + 命令；
  3. **不做**：核弹发射逻辑、弹头实体/爆炸/倒计时、对 CCNR-Com / CC-api 的任何调用或依赖。

## 2. 阵营属性

### 2.1 数据（`config/ccnr_rp/factions.json`）

```json
{
  "id": "qdf",
  "name": "QDF司令部",
  "attributes": [
    {"id": "minecraft:generic.max_health", "amount": 40, "operation": "add"},
    {"id": "minecraft:generic.armor", "amount": 4, "operation": "add"},
    {"id": "minecraft:generic.movement_speed", "amount": 0.1, "operation": "multiply_base"}
  ]
}
```

- `id` 一律写**属性注册名**（`namespace:path`）；`operation` ∈ `add` / `multiply_base` / `multiply_total`
  （缺省 `add`）；单阵营上限 16 条（`AttributeProfile.MAX_ENTRIES`）。
- 字段可选；缺省 = 无属性加成。解析/校验在**纯类** `AttributeProfile`（无 MC import，可脱机单测）：
  非法 id / 未知运算 / 非有限数值 / 血量加法非正 / 超上限 → 拒绝保存且**不做部分提交**；
  同（id+运算）重复声明 → 后者覆盖 + WARN。
- 结算顺序与原版一致：`v = (base + Σadd) × (1 + Σmultiply_base) × Π(1 + multiply_total)`（纯函数 `resolve`，可测）。

### 2.2 套用时机（唯一入口 `AttributeService`）

| 时机 | 行为 | 为什么 |
| --- | --- | --- |
| 部署（`SpawnFramework.applyDeployCore`） | 清背包后、`resetPlayerState` **之前**套用 | `resetPlayerState` 用 `getMaxHealth()` 回满；顺序反了会按旧上限回满（改血量后出门不是满状态） |
| 登录（`CCNRRPMod.onPlayerLoggedIn`，在场玩家） | 按当前配置重套 | 永久修饰随存档保留，重连后与配置对齐 |
| 管理面板/命令保存 | 该阵营**在线**成员立即重套 | 服务端权威 + 所见即所得（docs/01 §11.2） |
| 退场（死亡/判死/退役） | `AttributeService.clear` 卸下修饰 | 观察者不带上一局的加成 |

- 幂等：本 mod 施加的修饰名一律带 `ccnr_rp:attr:` 前缀，套用前先清理同前缀修饰（确定性 UUID + 前缀清理），
  重复部署/换阵营/重连都不会叠加成第二份加成。
- **未注册 id 不算配置错误**：执行期跳过并 WARN（"装对应 mod 后生效"）。这是"原版优先、mod 自然扩展"的解耦点——
  适配层不认识任何具体 mod，只认注册名。

### 2.3 FirstAid 适配（为什么需要、怎么保证不炸）

FirstAid（modid=`firstaid`）把原版血量换成 **8 个部位各自的血量上限**：原版 `generic.max_health`
只被它用于显示钳制（`SynchedEntityDataHelper` 里 `min(原版血量, max_health)`），
真正的伤害与死亡判定走部位血量。所以"改血量"必须翻译成**缩放部位血量上限**：

- 倍率 = `resolve(attributes, "minecraft:generic.max_health", 20) / 20`；对每个部位
  `setMaxHealth(round(initialMaxHealth × 倍率))` 后 `heal(上限)` → **出门即满状态**；
- 未配置血量时按 `initialMaxHealth` **复位**（换到无属性阵营不会残留上一阵营的放大血量）；
- 适配层是 `PlayerAttributeBridge` 内的私有内部类，**纯反射**（capability 静态字段 + `getMaxHealth`/
  `setMaxHealth`/`heal` 三个公开方法）+ `ModList.isLoaded("firstaid")` 探测 + 全程 `try/catch Throwable`：
  **不引入任何编译期依赖**（不新增 mods.toml 依赖、不新增 libs/ jar、不动 CI 取依赖流程），
  与 `CamSceneBridge`（CMDCam）同一套"可选依赖、缺失降级"纪律。
- **如何失效**：FirstAid 改 API → 反射失败 → 记一次 WARN，属性其余部分照常生效，血量保持 FirstAid 原值；
  不崩服、不改一半。若要类型安全，可后续按 docs/01 §8 为它补 `compileOnly` jar + fetch 脚本（届时需同步 mods.toml 与 ProjectMetadataTest）。

## 3. 区域（拓展设定）

### 3.1 数据（`config/ccnr_rp/areas.json`）

```json
{
  "version": 1,
  "areas": [
    {"id": "reactor", "name": "反应堆大厅", "dim": "minecraft:overworld",
     "x1": 10, "y1": -60, "z1": 10, "x2": 40, "y2": 80, "z2": 40}
  ]
}
```

- 轴对齐长方体、坐标**闭区间**；两个角点可任意顺序填写（判定时归一化 min/max，防"填反了就静默不生效"）。
- 校验（纯类 `AreaRegistry`）：id 小写 1-64、`dim` 必须 `namespace:path`、坐标必须有限、
  **任一轴零厚度（退化区域）拒绝**（永远不会命中的"看不见的墙"必须当场报错）、上限 64 个、同 id 后者覆盖 + WARN。
- 写入路径：`AreaService`（唯一读写入口）→ `ConfigStore.save`（DB 启用时进 `config_documents`，否则原子写磁盘）；
  写完换只读缓存；`ServerStopping` 清空（对称清理）。
- **引用完整性**：保存阵营弹头目标时会校验区域存在（不存在 → 拒绝保存并提示）；删除区域时会自动清空
  指向它的阵营 `warheadArea`（防悬挂引用让外部功能拿到无效目标）。管理面板删除前的影响预检会列出
  引用该区域的阵营（"弹头目标引用"行）。

### 3.2 对外接口（单向依赖：外部 → 本 mod）

- `CCNRRPMod.areas`（`AreaService`）：`areas()` / `find(id)` / `at(dim,x,y,z)` —— 只读查询，外部功能按 id 取区域。
- 阵营侧：`FactionManager.warheadEnabled(id)` / `warheadArea(id)`，同样的数据也在 `factions.json` 与
  `CharacterListS2C` 投影里（管理面板/外部工具都能读）。
- 命令：`/rp area list|info <id>|at <x> <y> <z> [dim]|add|remove`、
  `/rp attribute list|get|set|remove|clear`（权限 `ccnrrp.admin.area` / `ccnrrp.admin.attribute`）、
  `/rp faction warhead <阵营> <true|false> [区域id]`（权限 `ccnrrp.admin.faction`，与管理面板同一写入口）。
- **参数类型注意（实机验证发现）**：命名空间 id（`minecraft:generic.max_health`、`minecraft:overworld`）
  必须用 `ResourceLocationArgument`，不能用 Brigadier 的 `word()`（只吃 `[a-zA-Z0-9_]`，会在冒号处报
  "Expected whitespace to end one argument"）；区域 id 允许点/横线，用 `string()` + 服务端 `AreaRegistry.validId` 校验。
- **本 mod 不执行任何发射**：外部功能拿到"谁有权 + 目标在哪"后自行执行；本仓库不依赖外部 mod。

### 3.3 为什么"选区域"要独立成一套

`RuleService` 里的 `zoneToggle` 的"目标区"过去只是一个**自由字符串**（`Map<String,Boolean>`，无坐标、无校验、
且 `zoneEnabled` 无生产调用方）。区域注册表把"区域"变成有定义、有校验、有查询的数据：
外部功能与规则系统都可以用 `AreaService.at(...)` 做真实的位置判定，而不是各自维护坐标副本。

- **阵营页签**：入场电影两个开关所在行改为**三连开关**（全屏黑 / 简洁模式 / **可否启动弹头**）——

  遵守 docs/01 §10 弹窗三条件（隐藏下层 + Esc 只关弹窗 + 关闭清理输入框），已登记进 §10 表格。
