# P17 自定义设定（全局变量 + 预设）（docs/17）

> 一句话：**管理面板与命令都能对"变量"做增删改查，值可以直接被命令读走、被界面预览、被预设一键切换；
> 本 mod 只做这一件事——变量的定义、校验、持久化与只读取值接口。**

## 1. 需求与边界

- 维护者需求：*"搞一下那个授权方式，改成自定义设定区，就是可以创建变量，然后可以用命令或者 GUI 进行 CRUD，
  命令读取直接返回值，然后可以预览值，可以创建预设值点击直接切换（预设值也要 CRUD）"*。
- 这是 issue #3「特殊按钮」的**替代方案**：2.24.0 那种"为某一种功能（弹头）硬编码一对字段 + 一个区域注册表"的做法
  被整体删除（见 docs/16 §5）。**需求方需要什么开关，就自己建一个变量**，本 mod 不再为具体功能开字段。
- 交付边界：
  1. 变量（bool/number/text）+ 每变量预设值 + 整套预设方案的定义、校验、持久化、CRUD；
  2. 管理面板「自定义设定」页签（列表 / 取值预览 / 表单 / 预设胶囊点击切换）；
  3. 命令 `/rp var …`（含 **`get` 只打印裸值**，命令方块/RCON 可直接消费）与对外只读取值 API；
  4. **不做**：任何具体功能的解释（"这个开关代表核弹许可"是**外部功能**的事）、脚本表达式、变量作用域
     （阵营/职业/玩家级）、变量变更事件广播。

## 2. 数据模型

变量是**全局的**（无作用域）：需要"每方一份"就分别建 id（如 `permit_mtf` / `permit_chaos`）。
这样做的理由：作用域一旦进入模型，就必须回答"部署时快照还是实时读""退场后残留怎么办"，
而这两问的答案取决于**消费方**的语义——本 mod 不该替消费方作主。

### 2.1 变量（`config/ccnr_rp/variables.json`）

```json
{
  "version": 1,
  "variables": [
    {
      "id": "permit_mtf",
      "type": "bool",
      "name": "MTF 启动许可",
      "desc": "外部功能读取：本局是否允许启动",
      "value": "false",
      "presets": [
        {"id": "on",  "name": "允许", "value": "true"},
        {"id": "off", "name": "禁止", "value": "false"}
      ]
    }
  ],
  "schemes": [
    {"id": "round_default", "name": "默认局", "values": {"permit_mtf": "false"}}
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | `[a-z0-9_.-]{1,64}`（`VariableRegistry.validId`）；命令/对外 API 的寻址键 |
| `type` | `bool` / `number` / `text`，决定取值归一化与校验 |
| `name` / `desc` | 显示名（空则回退 id）/ 说明；界面与命令输出用 |
| `value` | 当前值，**已归一化的字符串**（数值型也存字符串，保证"读到的就是盘上的") |
| `presets[]` | 该变量的命名候选值：`{id,name,value}`，点击即把 `value` 切过去 |

类型归一化（`VariableType.normalize`，纯函数）：

- `bool`：`true/false/on/off/yes/no/1/0`（大小写不敏感）→ `"true"` / `"false"`；其余非法。
- `number`：必须是有限数字；**整数值写成不带小数的形式**（`1.0` → `1`），非法/NaN/Infinity 拒绝。
- `text`：去首尾空白，长度 ≤ 256（`MAX_VALUE_LEN`）；允许空串。

上限：变量 128 个、方案 32 套、每变量预设 32 个（`VariableRegistry.MAX_*`）。

### 2.2 预设的两级粒度（都要，因为回答的是两个问题）

| 粒度 | 回答的问题 | 交互 |
| --- | --- | --- |
| 每变量 `presets` | "这一个开关切到哪一档" | 面板里点胶囊即切换该变量；`/rp var preset apply <id> <preset>` |
| 整套 `schemes` | "整局参数一起换一套" | 面板里点方案胶囊即整套套用；`/rp var scheme apply <id>` |

- **方案 = 命名快照**：只含被列出的变量，**未列出的变量保持原值**（不做"未列出的重置为默认"——那会在
  管理员新增变量后被静默改掉，更难排查）。方案里引用了不存在的变量 → 保存时拒绝（`upsertScheme`）。
- **删除变量会自动摘掉所有方案里对它的引用**（`VariableService.delete`）：否则整份配置会因
  "引用了不存在的变量"而被全量校验拒绝落盘，管理员会陷入"删不掉变量也改不了配置"的死局。

## 3. 服务端

### 3.1 唯一读写入口 `VariableService`

- `com.ccnrcom.rp.variable.VariableService`（`CCNRRPMod.variables`）：`ServerAboutToStart` 构造、`ServerStopping` 清空
  （对称清理，静态态不跨世界残留）。
- 权威源是**配置文件**（经 `ConfigStore`：`db.enabled=true` 时进 `config_documents`，否则原子写磁盘）；
  类内的 `variables()`/`schemes()` 只是**只读镜像缓存**。写入一律
  **"读整份 → deepCopy → 改 → 全量校验 → 落盘 → 换缓存"**：任何一条非法即整体拒绝，不做部分提交（docs/01 §9.3）。
- 容错：启动/重载时单条非法只记 ERROR 并跳过该条，服务继续可用（不让一处手改错字整块失效）。

### 3.2 对外只读取值 API（单向依赖：外部 → 本 mod）

```java
var svc = com.ccnrcom.rp.CCNRRPMod.variables;   // 未就绪时为 null（服务端未启动）
String raw   = svc.raw("permit_mtf", "false");  // 原始值，不存在返回默认
boolean flag = svc.bool("permit_mtf", false);   // 按布尔语义取值（类型不符也算未配置）
double  num  = svc.number("count", 0d);         // 按数值语义取值
String  txt  = svc.text("label", "");           // 按文本语义取值
```

- **只读**：外部功能只能取值，写入只经命令/管理面板（走同一份校验），避免外部绕过校验把配置写坏。
- 值语义固定为"字符串 + 按需解释"：`bool`/`number` 取不到或类型不符时**返回调用方给的默认值**，
  不抛异常（外部功能不该因为管理员改了个类型就崩）。

### 3.3 管理 CRUD 通道

客户端发 `ManagerCrudC2S(kind, action, payload)` → `CharacterService.onManagerCrud`：

| kind | action | payload | 说明 |
| --- | --- | --- | --- |
| `var` | `create` / `update` | `{id,type,name,desc,value,presets[]}` | `create` 对已存在 id 报错（防误覆盖）；`update` 整条覆盖 |
| `var` | `set` | `{id,value}` | 只改当前值（轻量，按类型归一化） |
| `var` | `delete` | `{id}` | 删变量并摘除方案引用 |
| `var` | `presetApply` | `{id,presetId}` | 点击预设即切换取值 |
| `scheme` | `create` / `update` | `{id,name,values{}}` | 整套方案 upsert（`values` 逐项按变量类型归一化） |
| `scheme` | `apply` / `delete` | `{id}` | 一键套用 / 删除 |

- 权限节点 `ccnrrp.admin.var`（`Permissions.ADMIN_VAR`，可单独授权；OP≥2 亦可），
  在 `CharacterService.crudNode` 里由 `kind ∈ {var, scheme}` 选中；客户端只是发起意图，判定一律在服务端。
- 校验失败 → `sendError` 回显错误串；成功 → 编辑者全量刷新、其余玩家异步广播（与其他 kind 同一条路径）。
- 回显：`CharacterListS2C` 顶层新增 `variables` / `schemes` 两个数组（客户端只读列举）。

## 4. 命令（`/rp var`，权限 `ccnrrp.admin.var`）

```
/rp var list                                  列出所有变量（id | 类型 | 当前值 | 预设数）
/rp var get <id>                              ★ 只打印裸值（无前缀/翻译），找不到则无输出且返回 0
/rp var info <id>                             类型 / 显示名 / 当前值 / 说明 + 预设清单
/rp var set <id> <值>                          设置当前值（值用 greedyString，文本可含空格）
/rp var create <id> <bool|number|text> <值>    新建（已存在则报错）
/rp var remove <id>                           删除（同时摘除方案引用）
/rp var preset list|apply|set|remove <id> [预设id] [值]
/rp var scheme list|apply|save|remove <id> [名称]
/rp var reload                                从存储重读（手改配置文件后用）
```

- **`get` 为什么必须打裸值**：命令方块与 RCON 的消费方式是"读输出/读返回值"，
  任何 `§` 装饰或"变量 X 的值是："前缀都会让 `execute store` 拿到垃圾。故 `get` 只发
  `Component.literal(value)`，找不到变量就不输出（返回 0）。要看元信息用 `info`。
- `scheme save <id> [名称]` = **快照**：把当前**所有**变量的值存成一套方案，
  避免在界面里逐个填 `values`。
- 补全：`RpSuggest.variables()` / `schemes()` / `presets("id")` 实时读镜像缓存。

## 5. 界面（管理面板「自定义设定」页签）

一段式布局：左侧列表 + 右侧编辑器，编辑器中三个子页签分三段承载全部字段。**为什么分段而不是纵向堆叠**：
管理面板最小高度只有 340px，堆叠会溢出可视区；分段后每段都在一屏内可读（docs/01 §10.1）。

| 子页签 | 内容 |
| --- | --- |
| 变量 | id / 显示名 / **类型（点击循环 bool→number→text）** / 当前值 / 说明 + 新建·保存·删除 |
| 预设值 | 当前变量的预设胶囊（**左键点击即切换取值**）+ 预设 id / 显示名 / 取值 + 新增·保存·删除 |
| 方案 | 方案胶囊（**左键点击即整套套用**）+ 方案 id / 显示名 + 新建·保存·删除 |

### 5.1 删除交互：右键 + 二次确认（2.25.1 修订）

删除**一律**先弹确认框，确认后才发包；Esc / 取消 = 丢弃（不执行）。入口有三处，都指向同一个确认流程：

| 位置 | 操作 |
| --- | --- |
| 左侧列表项 | **右键** = 删除该条目（变量子页签删变量、方案子页签删方案） |
| 预设值胶囊 | **右键** = 删除该预设值；左侧**勾选框** = 标记，多选后点「删除」批量删 |
| 方案胶囊 | **右键** = 删除该方案；左侧**勾选框** = 标记，多选后点「删除」批量删 |

为什么要改成右键：原来是"选中条目 → 点删除按钮"，而按钮删的是**当前表单里的 id**，
和"你刚才右键/点中的那一条"没有视觉绑定——手一抖就会删错对象。绑定到条目本身 + 二次确认后，
误删只可能来自"连续两次明确操作"。批量删除仍是"勾选 → 删除 → 确认"。

确认框是页签内自绘模态（`RpVariablesTab.renderConfirm`）：隐藏下层、吞掉全部点击与按键（防弹窗背后
输入框继续接收键入）、Esc=取消；主按钮走白底反色 + `ACCENT_TEXT`（docs/14 §2.1 可读性硬约束）。

> 该交互不是本页签特例：2.25.1 起**全管理面板**的删除统一为「右键条目 + 二次确认」，
> 规范与逐条核对清单见 **docs/01 §10.2**。

- 左侧列表随子页签切换（变量 / 预设方案），选中行即可编辑；行文字为 `名称 (id) = 当前值`。
- 取值预览：列表行与胶囊上直接显示当前值，不必点开就知道现在是什么状态。
- 写入一律发 `ManagerCrudC2S`，保存后由服务端权威回显（客户端不维护第二份真相）。
- 视觉一律走 `RpTheme`/`RpButton`/`RpRoundRect`；**任何浅色填充（选中行/主按钮）上的文字必须用
  `RpTheme.ACCENT_TEXT`**（docs/14 §2.1 / docs/01 §10.1 的可读性硬约束）。

## 6. 为什么这样做（而不是继续加专用字段）

- 上一个方案（弹头许可 + 目标区域）把"需求方的一句话"翻译成**两个硬编码字段 + 一套区域数据结构 + 一个专用页签**：
  需求一变（改成三种许可、改成按阶段生效），代码就得再改一轮，而真正需要这个开关的外部功能
  从未要求本 mod 理解"核弹"。
- 变量系统把这类需求收敛成一件事：**管理员定义数据，外部功能读取数据**。
  本 mod 不解释值的含义，因此不需要预判需求形态；`docs/16` 的核弹场景现在只是
  "建一个 bool 变量 + 一套方案"，不再有专用代码。
- 代价是**没有作用域**：需要"每方一份"就得建多个 id。这是刻意的取舍——见 §2 的理由。
