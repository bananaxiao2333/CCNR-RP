# P15 模式编排与多模式（提案）

> 状态：**部分已实现（2.22.0）**。已实现：模式文件夹化 + `modes.json` 登记/热切换 + `/rp mode` 命令 + 剧本配置按模式路由
> （phases/events/waves/animations）+ 阶段条件驱动（`advanceOn`）+ 内嵌默认不再播种模式（由管理员在配置目录自建）。
> 未实现（后续）：`ruleChange` 动作执行、`ending`/`/rp end`、波次队伍创建自动轮询移除、`switchPhase` 序列步骤、场景内自动开局。
> 参考配置已写入模组配置目录 `config/ccnr_rp`（`scpsl`/`tac_comp`），不在源码资源。实现前请逐节确认；标注「已有」的是当前已具备，「待新增」的是需要实现的部分。

## 1. 目标
让一场"戏"能由 **阶段** 给节拍、**事件** 扣扳机并打出（动画/通知/波次/规则/任务/切幕）、**波次库**按剧本补充人手、
**胜负结局**收尾；并能在一台服务器上**热切换多套玩法剧本（mode）**，全程由管理端随时介入。

## 2. 术语
- **mode（剧本）**：一整套「阶段 + 事件 + 波次库 + 动画 + 胜负结局」的集合，可整体激活/切换。
- **phase（阶段）**：有序的游戏状态（幕），由触发器/事件推进（**不按时长**）。
- **event（事件）**：绑定触发器、命中后执行一串动作的"剧情触发点"。
- **sequence（行为序列）**：事件/阶段上的脚本步骤（`WAIT`／`WAVE`／`COMMAND`／`FORCE_PICK`／`TRIGGER`），顺序执行，支持 `{{变量}}`。
- **wave（波次）**：增援定义（招谁/几个/落哪），**仅被脚本或命令召**。
- **ruleChange（规则变更）**：事件动作之一，临时改部署限制/目标区/增益/招募方式。
- **ending（结局剧本）**：`/rp end` 触发、收尾本轮并复位到"待启"的电影/结算。

## 3. 总体架构（分层 + 数据流）

```
外部/场景内触发器（cond/time/phase 边界/n 人数）
        │  命中
        ▼
   EventManager ──► 命中事件 × N
        │              │ 动作（含 WAIT 排序）
        ├──► AnimationEngine  播动画（FADE/TITLE/CAMERA/SOUND/PARTICLE/ACTIONBAR）
        ├──► notify           标题/动作条全服喊话
        ├──► WaveLibrary.load ──► RecruitManager  召波（邀请制/自刷）
        ├──► RuleService      变更规则（限职业阵营/目标区/增益/招募方式）
        ├──► TaskService      发任务/XP 奖励（供 P5 结算）
        └──► PhaseMachine.switchPhase  推进幕
        │
   PhaseMachine ──►（ON_PHASE_END → 下一幕 ON_PHASE_START）
        │
   /rp end 或场景外触发 ──► EndingScript（game_end 动画 + 通报 + 结算 + 复位"待启"）
```

一个 **mode** 激活后：`开局（场景内自动）→ 第 0 幕 → 事件按触发器跑 → 阶段按条件推进 → /rp end 收尾 → 复位待启`。

## 4. 详细设计

### 4.1 多模式（mode）—— 热切换
文件布局（每个模式一套，独立于全局公共配置）：

```
config/ccnr_rp/modes.json                      # 登记 + 当前激活
config/ccnr_rp/modes/<modeId>/phases.json
config/ccnr_rp/modes/<modeId>/events.json
config/ccnr_rp/modes/<modeId>/spawn_waves.json
config/ccnr_rp/modes/<modeId>/animations.json
config/ccnr_rp/modes/<modeId>/ending.json      # 结局剧本（动画+通报+结算）
```

```jsonc
// modes.json
{
  "version": 1,
  "active": "invasion",
  "modes": [
    {"id": "invasion",  "name": "攻防拔旗", "order": 0},
    {"id": "escape",    "name": "限时撤离", "order": 1}
  ]
}
```

- `mode list|info <id>|set <id>`（OP≥2 / `ccnnrp.admin.mode`）。
- **热切换 = 重读该模式全套配置 + 重置"剧本运行时"**（阶段回第 0 幕、清事件/波次的运行期状态、停掉正在播的动画），
  **不重置**玩家状态/档案/经验（公共部分全局共享，不属于单模式）。
- 切换时若上一幕仍在 RUNNING：先触发该幕 `ON_PHASE_END`（或直接标记作废），再切入新模式第 0 幕。
- **边界**：切换不持久化"未结束的剧本"；切换前的运行时态不恢复（先决条件：管理端应择机切换）。
- **失效模式**：新模式缺少某配置文件 → 记 WARN 并按"无该文件"加载空集（事件/波次为空即不触发），不因缺档而崩。

### 4.2 阶段状态机（纯事件/条件驱动，不按时长）
- 阶段 = 有序状态 `{id, order}`，**移除时长依赖**（`durationMinutes` 弃用或仅作展示）。
- 推进由**触发器**担当，二选一：
  - **某阶段自带 `advanceOn` 触发器**（`CONDITION`（死亡数/到达区域/清点/人数）/ `ON_TIME`）：命中 → 本幕 `ON_PHASE_END` → 下一幕 `ON_PHASE_START`。
  - **事件动作 `switchPhase`**：显式切到目标幕（或下一幕）。
- 进阶判定条件（`advanceOn` / `switchPhase` 目标幕）可引用事件里 `CONDITION` 复用同一套 `TriggerEvaluator`。
- 命令 `phase list|set <id>|advance` 仍可手动（管理端随时介入）。
- **边界**：末幕无 `advanceOn`/`switchPhase` 时停在末幕；跳幕直接 `ON_PHASE_END`/`ON_PHASE_START` 各触发一次，中间幕不触发。

### 4.3 事件动作面（承载开局 & 收尾）
触发器沿用 4 类（`ON_PHASE_START/END`、`ON_TIME`、`PERIODIC`、`CONDITION`），动作扩展并可排序：

| 动作 | 说明 | 现状 |
|---|---|---|
| `startAnimation` | 播一场动画 | 已有（P7） |
| `notify` | 标题/动作条喊话 | 已有 |
| `spawnWave` / `WAVE` | 召一波（波次库） | 已有（P8），但改为脚本/命令召 |
| `tasks` | 发 XP 任务（供 P5 结算） | 已有 |
| `ruleChange` | 变更规则（见 4.4） | **待新增** |
| `switchPhase` | 强制切阶段 | **待新增** |
| `WAIT` | 动作间延迟 | 已有 |

- 事件可作**开局剧本**：被"场景内自动"触发（如人数达到、`CONDITION`、定时）→ 激活模式进第 0 幕并跑后续事件。
- 事件可作**收尾前置**：`/rp end` 前的条件事件（如提醒撤离）。
- **边界**：动作失败（如波次 id 不存在 / 动画缺失）→ 记 WARN、跳过该项，不中断整条序列。

### 4.4 波次库（纯脚本/命令召）
- `spawn_waves.json` 只作**定义库**（`id/mode/teamIds/professionIds/factionIds/count/minLevel/deployAt/recruitTimeoutSeconds`）。
- **取消**"队伍创建自动轮询触发"（`SpawnFramework` 的 `teamIds` 轮询 diff 逻辑改为不自动召，或默认关闭、逐波可配）。
- 仅由 `sequence` 的 `WAVE <id>`，或 `/rp wave spawn <id>` 召。
- **边界**：脚本重复召同一波 → 复用现有"同波次 id 只触发一次"的幂等；波未结算又再召 → 按配置"另起实例"或拒绝（记 WARN）。

### 4.5 规则变更 action（`ruleChange`）
子类型（`type` 外层区分动作，子字段用 `rule`）：

```jsonc
// events.json 某动作
{"type": "ruleChange", "rule": "limitProfessions", "phase": "danger", "professions": ["s4_guard"]}
{"type": "ruleChange", "rule": "limitFactions",   "phase": "danger", "factions": ["qdf"]}
{"type": "ruleChange", "rule": "zoneToggle",      "zone": "evac_point", "on": true}
{"type": "ruleChange", "rule": "buff",            "target": "@a", "effect": "speed", "seconds": 30}
{"type": "ruleChange", "rule": "recruitMode",     "phase": "danger", "mode": "BOTH"}
```

- `limitProfessions / limitFactions`：限定本幕可部署/可被征召的职业、阵营（影响 `SpawnFramework` 选人与 K 面板显示）。
- `zoneToggle`：开启/关闭目标区（占领点/撤离点），作用于区域判定。
- `buff / nerf`：临时增益/限制（回血、冷却、移速、增援节奏），作用于状态与装备。
- `recruitMode`：本幕谁能收到邀请（`SELF_DEPLOY/RESURRECTION/BOTH`）。
- **边界**：规则变更以"幕"为作用域，幕切换时自动解除未持久化的变更；同一幕的冲突变更以后者为准（限频/去重）。

### 4.6 胜负/结束结局（`ending`）
- **不做自动判定**，由命令/外部调用方裁决并扣扳机：`/rp end [reason]`（`ccnnrp.admin.event`）。
- 触发 `ending.json` 剧本：`game_end` 动画 + 全服通报 + **结算**（胜/败/平 XP 或状态——本轮方案**不区分胜负方**，胜负信息由你们自行播报）+ **复位**阶段回第 0 幕、清事件/波次运行时，标记"待启"。
- 结局只做"本模式结束"一种，不内置攻/守/平。
- **边界**：结算动作幂等（重复 `/rp end` 只处理一次）；结算后到下一轮开始前的空窗期，事件/波次不再自动触发（除非命中"开局"触发器）。

### 4.7 生命周期（开局自动 + 收尾）
- **开局**：场景内自动——由某事件/条件触发（如 `CONDITION` 玩家数达到 N、`ON_TIME`、定时），激活模式、进第 0 幕。
- **进行中**：事件按触发器跑；阶段由 `advanceOn`/`switchPhase` 推进；管理端可随时介入。
- **收尾**：`/rp end`（或外部触发）→ 结局剧本 + 复位待启。
- **边界**：空窗期不自动触发；重复开局幂等（RUNNING 中不重复）。

## 5. 命令族（新增/扩充）
```
/rp mode  list | info <id> | set <id>            # 模式
/rp phase list | set <id> | advance              # 阶段（已有，扩充语义）
/rp event trigger <id>                           # 已有
/rp wave  spawn <id>                             # 新增：显式召波
/rp end  [reason]                                # 新增：触发结局/收尾
```
权限：`ccnnrp.admin.mode` / `ccnnrp.admin.phase` / `ccnnrp.admin.event` / `ccnnrp.admin.wave`。

## 6. 配置示例（invasion 模式）
`modes/invasion/phases.json`：
```jsonc
{
  "version": 1,
  "phases": [
    {"id": "approach", "order": 0,
     "advanceOn": {"type": "CONDITION", "cond": "ALIVE_COUNT", "op": ">=", "value": 10}},
    {"id": "assault", "order": 1,
     "advanceOn": {"type": "CONDITION", "cond": "SCOREBOARD", "objective": "capture", "op": ">=", "value": 1}}
  ]
}
```
`modes/invasion/events.json`：
```jsonc
{
  "version": 1,
  "events": [
    {"id": "assault_start", "enabled": true,
     "triggers": [{"type": "ON_PHASE_START", "phase": "assault"}],
     "hooks": {"startAnimation": "assault_alarm", "spawnWave": "qdf_reinforce"},
     "sequence": [
       {"type": "WAIT", "seconds": 5},
       {"type": "COMMAND", "command": "say [CCNR-RP] 进攻阶段开始：夺取目标点"},
       {"type": "ruleChange", "rule": "zoneToggle", "zone": "capture_a", "on": true}
     ],
     "tasks": [{"id": "take_a", "xp": 50}],
     "durationSeconds": 0}
  ]
}
```
`modes/invasion/ending.json`：
```jsonc
{
  "version": 1,
  "animation": "game_end",
  "notify": {"titleKey": "ccnr_rp.mode.invasion.end"},
  "resetToPhase": "approach",
  "reward": {"xp": 20, "applyTo": "@a"}
}
```

## 7. 与现有系统的映射 / 改动范围
- **已有**：触发器 4 类、动画 6 类、波次定义与"邀请制/自刷"、序列 `WAIT/WAVE/COMMAND/FORCE_PICK`、`/rp phase/event`、`/rp wave spawn`、任务/XP 结算。
- **待新增**：
  1. mode 文件夹化加载 + `modes.json` + 热切换（重读+重置剧本运行时）+ `/rp mode` 命令族。
  2. 阶段改**条件驱动状态机**（引入 `advanceOn`/`switchPhase`；弃用/降级 `durationMinutes`）。
  3. 事件动作扩展：`ruleChange`（4 子类型）、`switchPhase`。
  4. 波次库：**取消队伍创建自动轮询**（或逐波 opt-in），仅脚本/命令召。
  5. `ending` 剧本 + `/rp end` + 幂等结算 + 复位。
  6. 开局"场景内自动"（条件/定时触发激活模式）。
- **不新增**：公共部分（阵营/职业/档案/经验）不属单模式，全局共享。

## 8. 分阶段实施建议（WBS，按依赖排序，每步独立可用）
1. **地基**：`mode` 文件夹化加载 + `modes.json` + `/rp mode set`（热切仅重置剧本运行时）+ 配置示例。验收：切模式后阶段/事件/波次换成新模式且运行时复位。
2. **阶段状态机**：`advanceOn`/`switchPhase`，弃用时长。验收：条件命中自动切幕，`ON_PHASE_END/START` 各触发一次，跳幕行为正确。
3. **波次库纯脚本化**：取消队伍自动轮询（或逐波开关）+ `/rp wave spawn` + 幂等。验收：无队伍创建也只在脚本/命令召时冒波。
4. **规则变更**：`ruleChange` 4 子类型 + 幕作用域自动解除。验收：限职业/开目标区/临时增益/改招募模式按幕生效并在切幕复位。
5. **结局闭环**：`ending.json` + `/rp end` + 幂等结算 + 复位。验收：`/rp end` 播结局动画、通报、结算、UI 回"待启"，重复调用幂等。
6. **开局自动**：场景内条件触发激活模式。验收：满足条件自动进第 0 幕并跑事件。

## 9. 边界与失效（如何失效）
- 热切换不保留"未结束的剧本"；切换前运行时态不恢复。
- 缺配置文件 → 空集 + WARN，不崩。
- 动作失败（波次/动画 id 缺失）→ 跳过该项 + WARN，不中断整条序列。
- 结算/开局幂等；空窗期不自动触发。
- 所有"剧本运行时"状态的正确性不依赖"重新触发/重载"来恢复（按 docs/01 §9）。
