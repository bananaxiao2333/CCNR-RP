# CCNR-RP 数据库后端设计（docs/12）

> 自 v2.19.0 起，CCNR-RP 的数据持久化由「本地 JSON/TOML 文件」升级为「数据库后端」。本文档描述目标架构、
> 表结构、配置档、命令、迁移与失败模式。**默认 SQLite（内嵌单文件）；MySQL 可选**。

## 1. 总览

- **访问层**：轻量 JDBC 仓储/DAO + 注解微 ORM（`com.ccnrcom.rp.data`），`SqlDialect` 统一 SQLite/MySQL 差异。
- **存储模型**：管理配置按「配置档 × config_key」存 **JSON 文档列**；玩家/运行时数据用**规范化关系表**；音乐/图标存 **BLOB**；serverconfig 调参存 **`server_settings`**。
- **配置档**：多套命名配置档（`config_profiles` + `meta.active_profile`），启动按 active 读取，`/rp db profile select <id>` 运行中热切换。
- **未启用**（`db.enabled=false` 或无 `config/db.properties`）：全部降级为原有文件行为，零破坏。

## 2. 连接配置（config/db.properties）

```properties
db.enabled=true
db.mode=sqlite                 # sqlite | mysql
db.file=config/ccnr_rp/ccnr-rp.db
db.host=localhost
db.port=3306
db.database=ccnr_rp
db.user=ccnr
db.pass=${CCNR_DB_PASS}      # 可用环境变量 CCNR_DB_PASS 覆盖；日志掩码
db.poolSize=4
db.profile=default
db.fallbackToFiles=false
```

启动流程（`ServerAboutToStart`）：`Database.connect()`（建 schema + 播种 default 配置档）→ `CCNRRPConfig.applyDbOverrides()`（调参覆盖）→ 各管理器按 active 配置档加载。

## 3. 表结构（DbSchema，SQLite 与 MySQL 类型一致：TEXT / INTEGER / BLOB，布尔存 INTEGER 0/1）

| 表 | 列 | 主键 | 用途 |
|---|---|---|---|
| schema_version | version | version | 模式版本追踪（v1 初始 DDL） |
| meta | key, value | key | active_profile 等全局元数据 |
| config_profiles | id, name, active, created_at | id | 命名配置档 |
| config_documents | profile, config_key, json, updated_at | (profile, config_key) | 管理配置的 JSON 文档 |
| users | uuid, xp, last_create_at, any_support_revive, status, profession_id, faction_id, cooldown_until, duty_seconds | uuid | 用户档案（规范化） |
| user_pending_xp | uuid, rule_id, title, value, seq | (uuid, rule_id) | 待结算经验列表子表 |
| pending_notices | uuid, msg_key, args, seq | (uuid, seq) | 离线结算挂起通知 |
| team_waves_done | team_id | team_id | 已触发召唤波的队伍 |
| server_settings | profile, key, value, type | (profile, key) | serverconfig 调参（按配置档） |
| assets | name, kind, data(BLOB), size, sha256, updated_at | name | 音乐(.ogg)/图标(.png) 二进制 |

## 4. 配置档（多套命名配置）

- `default` 为默认档；`/rp db profile create <id>` 新建，`/rp db profile select <id>` 切换（写 `meta.active_profile` 并热重载全部管理器）。
- 切换后调用 `ConfigReloader.reloadAll()`（factions/settings/events/phases/waves/sequences/animations/experience rules）+ `broadcastConfigAll` 刷新客户端。
- 玩家/职位等运行时数据是 **per-world**（不在配置档内），切换时对配置引用重新校验并 WARN 悬空项。

## 5. `/rp db` 命令族（OP≥2 或 `ccnrrp.admin.db`）

| 命令 | 说明 |
|---|---|
| `/rp db status` | 显示后端/配置档/连接掩码状态 |
| `/rp db test` | 连通性测试（SELECT 1） |
| `/rp db migrate` | 本地 → 库（幂等）：config JSON + 运行时数据（user_profiles/pending_notices/team_wave_done）+ 调参 + 音乐/图标 |
| `/rp db export <dir>` | 库 → 本地备份（配置/调参/用户档案/素材） |
| `/rp db flush` | 强制刷新写后置（用户档案等落库） |
| `/rp db connect sqlite <file>` | 写 db.properties（sqlite），重启生效 |
| `/rp db connect mysql <host,port,db,user,pass>` | 写 db.properties（mysql），重启生效 |
| `/rp db profile list|create <id>|select <id>` | 配置档管理 |

## 6. 键代码路径

- **配置文档**：`ConfigStore.load/save`（DB 启用读库、否则回退磁盘文件）。`ConfigCrud` 与各管理器（FactionManager/ManagerSettings/EventManager/SpawnFramework/SequenceEngine/AnimationEngine/ExperienceService）均经此。
- **用户档案**：`UserRepository`（users + user_pending_xp，事务批量）；`UserService` 保持内存 Map 工作状态，load 从库读回、save 落库。
- **挂起通知/队伍触发**：`PendingNoticeStore`、`SpawnFramework.persistTeamState` DB 启用时存表。
- **调参**：`ServerSettingsStore` + `CCNRRPConfig.applyDbOverrides()`（保留 Forge SPEC 为运行时持有者）。
- **素材**：`AssetRepository`（assets BLOB）；`AssetLibrary` 清单/下发、`MusicStore` 上传/列表。

## 7. 失败模式与容错

- 连库失败且 `db.enabled=true` → fail-fast（数据完整性优先）；`db.fallbackToFiles=true` 或未启用 → 走文件并显式 WARN。
- 配置文档 JSON 损坏 → 沿用「ERROR + 保留 .bak + 跳过该条目」。schema 缺失 → 自动从 DDL 建。驱动缺失 → 明确提示补驱动。
- 密码：仅 environment/properties 读、日志掩码；DB 账号最低权限；`db.properties` 不进仓库（.gitignore）。

## 8. 线程与权限

- DB 写走专用单线程 executor（`Database.asyncWrite`），读走主线程 `Database.read`，单一连接 + ReentrantLock 串行化。
- **DB 线程严禁触碰 Level/NBT/实体/网络/渲染对象**（docs/01 §9.4）。写入遵循 docs/01 §9.2 服务端权威。
- 命令权限：`ccnrrp.admin.db`，回退 OP≥2。
