# CCNR-RP 界面主题设计 · 黑白灰军用终端（docs/14）

> 目标：把 in-game 界面视觉统一为「黑白灰军用终端」，与 Web 管理面板（ccnr-rp-gui / src/admin）保持一致。
> **主题 v4** 替换原 **v3「CCNR:NET 机密终端」**（冷暗科技金属底 / 青色主色 / 金·蓝徽章 / 高饱和正红选中）。
> **主题 v4.1（2.24.1）** 是 v4 的**令牌收口**：设计语言、调色板与布局不变，把散落在各界面里的裸色值
> 登记为语义令牌并抽出共享绘制入口，使「同类构件只有一种画法」（见 §2.1 / §5.4）。
> 本设计只改「视觉层」（颜色/描边/选中态/文字层级/容器装饰），**不触碰**布局、几何、行为、配置、网络、存档与运行时逻辑。

## 1. 设计语言（一句话）

> 近黑冷暗底 / 白·灰等宽文字 / 细灰边 / **白 = 强调**（选中反白）/ **红 = 警示危险** / **灰阶徽章**（机构等级）。
> 除红色警示外全程无彩色，仅以明度（白 > 亮灰 > 暗灰）划分层级。

- 底色：近黑（#000 ~ #141414），面板灰阶底、深色卡片。
- 文字：白（主）/ 亮灰（次）/ 暗灰（弱），等宽字体（MC 字体近似）。
- 边框：细灰（#333 / #666），四角 L 型角标。
- 强调：白色（按钮主操作、选中反白、游标、徽章亮阶）。
- 危险：正红（#FF3B30 / #FF4A40），唯一保留彩色。

## 4. 关键组件实现

- **terminalPanel / card**：近黑底 + 灰描边。
- **selectedBar（选中态）**：**白底反白字** + 白左线，对齐前端 selected 反白；选中行文字须用 `RpTheme.ACCENT_TEXT`（深色）以保证白底可读。
- **RpButton**：`primary`=白底黑字 / `secondary`=暗底灰边白字 / `danger`=红边红字。
- **RpScrollbar**：游标用 CYAN（现为白）。
- **RpIcons.badge**：灰阶环（按 tier）+ 白色图形。
- **tag()**：`"[ 分类 ]"`。
- **scanlines**：每 3px 一条微亮白线（屏幕质感）。

### 5.5 K 面板构成主义硬边化（2.24.1，仅 `CharacterManagementScreen`）

> 前几轮只做了「令牌收口」——外观几乎不变，于是被反馈「看不出变动」。本节是一次**克制的视觉强化**，
> 范围严格限定在 K 面板（`CharacterManagementScreen`）一个文件内：把构成主义语言做实（硬边直角 / 45° 对角线 /
> 红为结构色），把科技感做在「刻度·序号·读数」上，而不是加光效。

- **删除柔光，改硬边**：设计语言里「不要多层 alpha 光晕」这条此前没被遵守——预览区阵营水印用
  `RpIcons.bigBadge(alpha=36)`（多层同心 alpha 圆）叠成一团灰斑；全息底座用宽幅 `fillGradient` + 多层同心圆。
  现改为：**水印 = 双层 1px 细环 + 两段红色断弧 + 四向刻度 + 中心十字 + 单扇区 45° 排线**；
  **底座 = 2px 核心竖线 + 虚线侧柱 + 硬环 + 八向刻度 + 汇聚透视线 + 基线刻度尺 + 红色断弧**。
- **红升级为结构色**：`STRUCT_RED`（0xFFE03028）只用于线条/序号块/楔形/刻度，与「危险实心红」
  （`RED_BG_FILL`：整块红底白字）在用法上区分——前者是构图，后者是告警。
- **科技感三件套**：① **刻度**（面板/卡片底缘刻度尺、导轨每槽刻度、底座八向刻度）；
  ② **序号**（小节头红底反白 `01/02/03`、装备条目前缀 `01..05`）；③ **读数框**（内陷底 + 左红条 + 右缘刻度 +
  左右两端对齐），把 `ID // FACTION` / `LV.REQ` / `PERSONNEL` 从裸灰字变成机器读数。
- **排版**：小节标题 = 全大写 + 字距放大 + 尾部细线（`sectionHead`）；职业名 = 字距放大白字 + 硬边标题线。
- **边界**：新原语全部为 `CharacterManagementScreen` 私有方法，**未改动 `RpTheme`/`RpIcons`**，故其它界面零影响；
  布局常量（卡片 80px、装备行距、部署按钮位置、各区矩形）全部未动；未增删任何语言包键；
  窄窗口下 `sectionHead`/`readout`/装备序号会自动省略或截断，不溢出面板。
- **如何失效**：若日后把水印/底座改回多层 alpha 同心圆，或在小节标题里塞渐变，本节的「硬边」前提即失效；
  新增这类装饰请沿用本节原语（或先把它们提升为共享原语再复用），不要各写一套。

### 5.6 K 面板「编制席位」结构重设计（2.26.0，`CharacterManagementScreen` 结构性重构）

> **背景（为什么要换结构，而不只是配色）**：K 面板自 v1.0.4 起沿用「左导航列｜中列表列｜右预览列」的三栏网格。
> 该结构与本 mod 自身的历史包袱、以及**外部同类 RP/SCP 题材终端的通用三栏范式**（左＝机构/阵营清单、
> 中＝角色/职位清单、右＝身份预览＋装备槽＋属性文本块）在**信息架构层面高度同形**——即使代码逐行自研，
> 也容易被指认为"照搬界面"。因此本轮不是改色，而是**换掉信息架构**：三竖列不再存在，改为
> 「横向导轨 + 卡片网格 + 底部抽屉」三段式。语言键 `nav`/`position_list` 随结构一并删除
> （登记在 `LangFileTest.REMOVED_KEYS`），旧三栏列头不再是本 mod 的任何一部分。

**结构（零竖列）**

| 区域 | 内容 | 与旧三栏的差别 |
| --- | --- | --- |
| 头部 | `[CCNR] TERMINAL` + `LV.x // STATUS: y` + `[ ADMIN ]` + `✕`，下缘白色分隔线 | 保留（原样） |
| **顶部机构导轨** | 横向芯片带：`[ 全部 ]` + 各机构芯片（圆形徽章 + 方括号名），滚轮横移，溢出时下缘横向可拖动滚动条 | 机构过滤**从一整列变为一条 22px 横带**；芯片即过滤入口 |
| **中部席位卡网格** | 1~4 列自适应卡片：序号码块 / 职位名（字距放大）/ `LV.n` 等级门控标签 / 机构徽章＋机构名＋`在职/编制` 读数 / 紧凑装备图标条；左缘状态条 白=可部署·红=编制满·灰=等级未达；选中=整卡反白；纵向滚动条 | 职位从**单列文本行**变为**多列席位卡**，且**卡片自带装备图标条**（旧版装备只在右栏出现） |
| **底部席位终端抽屉** | 选中项横向三段：3D 立绘（含 `// PREVIEW` 标签与机构徽章底标）｜身份读数（`ID // FACTION`、`[ LV.REQ \| CURRENT ]`、`PERSONNEL // FACTION`）＋职业画像（`02 PROFILE`）｜装备槽（`01 EQUIPMENT`，槽下带槽名）+ `[ DEPLOY ]` 按钮 | 详情**从常驻右栏变为随选中更新的底部抽屉**，且是横向排布（旧版是竖排右栏） |

**交互**：点击席位卡＝选中（抽屉即时更新）；点击导轨芯片＝切换机构过滤（并清空选中、回到首行）；
滚轮在导轨上＝横移、在网格上＝翻行；方向键在网格内移动选中（自动滚入可视区）；`Esc` / `✕` 关闭；
部署按钮的**全部判定条件与旧版逐条一致**（等级门控、观察/在场可部署、阴间禁用、冷却、职业与阵营在职上限、
在场换岗按"不含本人"计），网络包与服务端强校验未变——本轮是**纯客户端呈现层重构**。

**降级（不溢出终端框，2.26.2 修"很多空行"）**：**网格只占整数行**——行数由可用高度定（1~12 行，卡片高在 44~62 之间取），
网格高度 = 行数×卡高 + 行间距，**多出来的高度全部还给底部抽屉**；这样网格下缘永远不会留出一条
"什么都没有"的空白带（实机反馈的"很多空行"就是这里）。窗口很矮时先收起机构导轨那一行、再压缩抽屉，
网格被压到 20px 以下则整块不画（只留抽屉）；网格与抽屉之间始终保留 8px 间隔；内容层整体裁剪到终端框内。
抽屉三段（立绘 / 读数 / 装备+按钮）各自独立判空间，窄窗口下先让位给读数与部署按钮，绝不互相压字。

**滚动（2.26.2 修步进/卡顿，2.26.3 改像素级 + 逐帧缓动，有中间态）**：
1. **单位是像素，不是"行/格"**：三处滚动区都保存「当前值 / 目标值」两档浮点量（`gridScroll`/`railScroll`/`profileScroll`
   与各自的 `…Target`）。滚轮与方向键**只改目标值**，实际位移由 `advanceScroll()` 在 `render()` 每帧按
   `k = 1 − e^(−dt/55ms)` 逼近——于是内容是一格一格**滑过去**的，不是直接跳上去（"没有滚动感"的根因就是
   逐格对齐 + 整数跳变）。缓动按真实帧间隔算，帧率高低手感一致；拖滚动条则当前值**直接**跟随光标（1:1 跟手，
   不做缓动，否则会有拖不动/拖过头的错觉）。
2. **滚轮每格一动**：`delta` 本身≈±1，**不能写 `delta / 10`**——会被 int 截断成 0，表现为"滚轮没反应"（见 §5.7）。
   网格一格 = 一个行距（卡高+间隔），导轨一格 = 一个芯片档位，画像一格 = 一行（10px）。
3. **游标与命中都用"当前位移"**：滚动条游标按 `…Scroll`（当前）画与命中，滚轮缓动时游标与内容一起滑，
   不会先跳到终点；命中判定同样按当前像素位置算（`cardIndexAt`），半行滚动时点哪张卡就是哪张卡。
4. **裁剪与词条**：网格带整体 `enableScissor`（半行滚动时卡片被干净地裁掉一截，不会压到标题/抽屉），
   物品词条改为收集后在裁剪之外绘制（否则贴边时会被裁掉）。
5. **性能**：纯滚动只走 `relayout()`（重算命中区），**不**调 `rebuild()`——后者每次都 `clearWidgets() + new Button`，
   每个鼠标事件重建一次 widget 是"卡顿"的根因；只有"换人/换筛选项"这类改变部署按钮状态的操作才需要 `rebuild()`。

**空装备不铺空槽**：职位 loadout 一件都没有时，装备条画一条暗刻度 + 「无装备 / NO LOADOUT」，
而不是 5 个空槽框（后者一眼看去就是一排"空行"）。

- **边界**：只改 `CharacterManagementScreen` 一个文件（新原语仍为该文件私有方法）＋新增 3 个语言键
  （`ccnr_rp.gui.character.muster` / `.dock` / `.equip.none`）＋删除 4 个随结构消失的死键；`RpTheme`/`RpIcons`/`RpButton`
  未改（`RpScrollbar` 仅 §5.7 的横向拖拽补齐）；配置 / 网络 / 存档 / 服务端零改动。
- **如何失效**：①若日后把机构过滤改回左侧竖列、或把详情改回常驻右栏，"零竖列"这一差异化前提即失效；
  ②若席位卡去掉装备图标条，卡片与普通列表行的区别消失；③若新增分区忘记走 `sectionHead`/`readout`
  这两条本地原语，序号/刻度语言会各写一套。以上任一条被打破，请在本节更新契约并说明理由。

### 5.7 滚动交互统一「可滚 = 可拖」（2.26.1；K 面板平滑滚动见 2.26.3）

> **契约**：任何会溢出的滚动区，**滚轮能滚就必须能拖**，且必须画出滚动条——不允许出现
> 「只能滚轮、看不见也拖不动」的死区，更不允许画出滚动条却拖不动（假供能）。溢出时才出现滚动条；
> 未溢出只画低透明度轨道，不占内容宽度（内容侧按"是否溢出"动态让出 6~8px 槽位）。

- **共享原语（唯一入口）**：`RpScrollbar.clickV/clickH`（命中游标 → 开始拖拽；命中轨道 → 跳转）、
  `dragV/dragH`（按轴向换算偏移）、`dragId()`（拖拽分发）、`endDrag()`、`draw/drawH`（渲染）。
  竖直与横向共用同一套拖拽状态，靠内部 `dragHorizontal` 区分轴向——**新增滚动区一律走这套，不要自写拖拽**。
  2.26.1 为横向补齐了 `clickH/dragH/offsetFromDragH`（此前横向只有 `drawH`，画出来却拖不动）。
- **id 分配**：拖拽按 `dragId` 分发，故 id 必须全局唯一。约定：K 面板 1=席位网格 / 2=机构导轨 / 3=抽屉画像；
  管理面板 0=面板列表 / 7=设置页 / 9=图标选择弹窗 / **30 起为页签内滚动条**（31/32=经验规则列表·参数面板、
  33=自定义设定胶囊带、34/35=关系页签 from·to 下拉、36=阵营组页签下拉）；
  事件横幅 41（背包界面之上的浮层，独立于 Screen）。
  管理面板 `mouseDragged` 见 `dragId >= TAB_SB_BASE` 即路由回发起拖拽的页签，避免落到面板自身的 `scroll`。
- **覆盖清单（2.26.1）**：K 面板（席位卡网格纵向 / 机构导轨横向 / 抽屉职业画像纵向）、
  经验规则页签（规则列表 + 参数面板）、自定义设定页签（预设值·方案胶囊带横向）、
  关系页签（来源·目标阵营下拉）、阵营组页签（阵营下拉）、事件横幅（背包界面上的横向条，
  经 `ScreenEvent.MouseButtonPressed/MouseDragged/MouseButtonReleased` 转发，未命中不抢原生点击）。
- **如何失效**：①新增溢出区只接滚轮不接拖拽（或反之）即违反本节契约；②沿用新的滚动条 id 而不登记、
  或复用已占用 id，会让拖拽被别的界面吃掉；③事件横幅这类"非 Screen 浮层"若改为自行处理鼠标而不做
  「命中才取消事件」，会抢掉背包的原生点击。

### 5.8 背包左侧「对局状态」面板与展示三件套（2.26.6）

> **背景**：顶部事件横幅过去直接画内部 id（`g.drawCenteredString(font, Component.literal(id)...)`）——
> 玩家看到的是 `qdf_support` 这种英文串；而客户端当时**完全没有**"当前模式 / 当前是哪一幕"的镜像，
> 背包界面里看不出这一局进行到哪了。本轮补上：配置侧给模式/阶段/事件加"显示名·描述·图标"，
> 网络侧新增 `MatchStateS2C`，界面侧新增左侧面板并改造横幅。

**展示三件套（`DisplayInfo`）** —— 模式 / 阶段 / 事件共用一份值类型（纯逻辑、可脱机单测）：

| 字段 | 说明 |
| --- | --- |
| `name` | 显示名。**空则回退实体 id**（界面永不露空串） |
| `desc` | 描述。按像素断行（`RpTheme.wrapText`），横幅最多两行、面板按卡片高度自适应 |
| `icon` | 图标：内置矢量图形名（`hex/shield/claw/storm/eye/target/cross/gear/helm/chest/back/heart`）或 `img:<名>`（服务器素材库图片）。空 = 不画 |

**图标画法（用户指定：「半遮挡在卡片左下角，出卡片部分裁剪」）**：
圆心**落在卡片左下角顶点**上，再 `enableScissor(卡片矩形)` 裁一次 → 伸出卡片的那一半被裁掉，
只剩卡片内的四分之一。因此：
1. 卡片底部预留 `ICON_RESERVE = 14px` 的**空白带**，文字永远不会压到图标上；
2. 图标走 `RpIcons.icon`（**无底盘、无等级环**的裸图形）——用带盘/环的 `badge` 会在裁剪下露出脏边；
3. 面板与横幅**共用同一画法**，不要各写一套。

**左侧面板「对局状态」（`MatchStatusPanel`）**：
- 位置：背包界面（`InventoryScreen`）左侧、纵向居中；卡片宽度上限 150px，按可用空间收缩。
  **可用宽度 < 86px 则整块不画**（窄窗口降级，绝不压背包本体）。
- 内容：**模式卡**（`[ 游戏模式 ]` + 显示名 + 描述）与**阶段卡**（`[ 回合阶段 ]` + 显示名 + 描述 +
  底部计时读数）。阶段卡带红色状态条/警示底（本局正在推进），模式卡用中性底。
- 计时读数（右上角数字，左标签右数字的机器读数观感）：
  | 读数 | 数据源 | 倒数时钟 |
  | --- | --- | --- |
  | 本幕剩余 | 时长驱动幕的 `durationMinutes`（`PhaseClock.ticksRemaining`） | **tick**（游戏暂停时停住） |
  | 下一步 | 行为序列下一个待执行步骤（`SequenceEngine.nextStepInMs`） | **墙钟**（服务端 `dueAtMs` 就是墙钟，暂停期间照样到期） |
  两种都支持、有几种画几种；条件驱动幕（`advanceOn`）**没有**本幕剩余读数，纯 `WAIT` 剧本的计时来自"下一步"。
  **两种计时必须用两种时钟**——用错会出现"暂停后倒计时对不上"。剩余 ≤10 秒转红。
- 空窗期（`/rp end` 之后）在卡片下方加一行 `本局已结束 · 等待开局条件`。
- **从未收到对局状态时整块不画**（`ClientCharacterState.matchStateSeen`）：连了未装本 mod / 通道不可用的
  服务器时，不该出现"未启用模式"这种并非事实的假状态（docs/01 §9.6 不显示假数据）；换服重连时该标记复位。
- 本面板当前**纯只读**：不注册任何鼠标/键盘处理。管理员快速操作经用户决定暂缓，方案见 `mod/TODO.md §1`。
- 只在背包界面绘制（与 `StatusHud`/`EventBanner` 同一挂载点 `ScreenEvent.Render.Post`），
  且 `CinematicController.active()` 期间不画。

**同步（`MatchStateS2C`）**：一次给全"模式 / 当前幕（含 `index/total`）/ 两种剩余毫秒 / 激活事件三件套"。
**只传剩余毫秒，客户端本地倒数**——不每秒发包、也不受两端时钟偏差影响（docs/01 §9.2）。
推送时机：登录补发、切幕、事件开始/结束与 `clear`、`/rp end` 复位、模式切换、序列启动与每步落地。

- **边界 / 如何失效**：①卡片不再预留底部空白带、或用 `badge`（带盘）画角标 → 半遮挡图标会被裁出脏边、
  文字压图标；②只改模式/阶段而忘了事件，横幅会退回画 id；③新增"会溢出的状态区"只接滚轮不接拖拽
  → 违反 §5.7 契约（本面板只读、不溢出，暂不涉及）；④把两种计时的时钟用反
  → 暂停/恢复后倒计时与真实推进对不上。

### 5.9 阵营属性档案弹窗修复 + EditBox 占位符契约（2.26.7）

> 实机反馈的四条里，前三条是**可复现的渲染/交互缺陷**（第四条"角色级属性覆盖"是需求，见 `mod/TODO.md`）。
> 三条根因各自不同，逐条记下来防回退。

**① 占位符必须用 `setHint`，绝不能用 `setSuggestion`**（最重要的一条）：

| API | 原版行为 | 该用在哪 |
| --- | --- | --- |
| `setHint(Component)` | 仅在 `hint != null && value.isEmpty() && !isFocused()` 时绘制 | **占位提示** |
| `setSuggestion(String)` | 追加在**已输入文本之后**的灰色补全串 | 补全剩余部分（本 mod 不用） |

- 判据来自原版字节码（`EditBox.renderWidget`）：`hint` 的绘制被 `value.isEmpty()` 与 `!isFocused()` 双重把关，
  而 `suggestion` 直接 `drawString` 在已输入值之后。
- **实测缺陷**：`attrBox`（属性档案弹窗）与 `seqBox`（流程编辑器参数）都用 `setSuggestion(占位符)`，
  于是聚焦后出现 `adadadad属性 id` —— 输入内容与占位符糊在一起、且不消失。
- 自检：`grep -rn "\.setSuggestion(" src/main/java/com/ccnrcom/rp/client/` 应为 **0 处**（占位提示一律 `setHint`）。
  本 mod 的 id 补全走自己的 `suggestionPopup`/`suggestionRow`，不需要原版补全串 API。

**② 长文案必须断行/裁剪**：属性弹窗顶部提示行此前是单行裸 `drawString`，会一路画到弹窗外面
（实测拖到屏幕右缘）。现改为 `RpTheme.wrapText` 最多两行、仍放不下时末行用 `RpTheme.clip` 裁出省略号；
弹窗标题同样走 `clip`（阵营 id/显示名可能很长）。该提示文案也精简到两行内可读完。

**③ 属性 id 补全**：新增 `SugSource.ATTRIBUTE`，候选 = 服务端同步的**已注册属性 id**
（`ManagerStateS2C.attributeIds`；主线程只扫一次注册表，再按玩家复制，docs/01 §9.6）。
两个顺序约束（与 §2.1 的「下拉/补全」同一契约，写错就点不到候选项）：
- **绘制在弹窗内容之后**（`renderAttributeModal` → `resolveIdSugSource()` → `renderIdSuggestions()`），
  否则被行输入框盖住；
- **命中在 `attributeModalOpen` 吞点击之前**（该分支原本无条件 `return true`，会把候选项点击一并吞掉）。

- **如何失效**：①任何新输入框再用 `setSuggestion` 当占位符即复现"糊字"；
  ②把补全绘制/命中顺序挪到弹窗之前，候选项会被弹窗吞掉（点不动）；
  ③新增 id 类输入框忘记接 `resolveIdSugSource()` / `idSugCandidates()` 就没有补全；
  ④弹窗内新增长文案若不走 `wrapText`/`clip` 会再次"出框"。

### 5.10 世界空间绘制必须保留 alpha（2.26.11，头顶标签徽章隐形）

**契约：世界空间（`RenderLevelStageEvent` 等阶段、用 `MultiBufferSource.getBuffer(RenderType.*)` 绘制）
的颜色一律用完整 ARGB，禁止 `& 0xFFFFFF` 抹掉 alpha。**

- **实机现象**：观察者视角下看别人头顶的悬浮标签，**文字与血量都正常，只有阵营图标看不见**
  （用户的 10 个阵营里 9 个用 `img:<名字>` 图片图标，全部中招）。
- **根因（2.25.1 主题迁移引入的回归）**：`PlayerNametagRenderer` 的 7 个颜色常量在迁移到 `RpTheme`
  时被写成 `RpTheme.XXX & 0xFFFFFF`，把 alpha 抹成了 `0`。而这个错误的可见性是**分裂的**：
  - **文字**走 `Font.drawInBatch`，原版 `Font` 有兜底 —— 颜色 alpha 为 0 时被强制或上 `0xFF000000`
    （`Font.m_92719_`，字节码 `(color & 0xFC000000) == 0 → color | 0xFF000000`）。所以**文字照常显示**，
    这正是本次最难判的地方：看起来"只是图标没加载"。
  - **几何图形**（`RenderType.gui()` 的矩形/圆盘/扫描线多边形）与**纹理**
    （`RenderType.entityTranslucent` 的图片徽章 quad）**不走 Font**，alpha=0 原样生效 → **整块全透明**。
- **影响面**：徽章底盘（`COLOR_BADGE_DISC`）与挖空细节（`COLOR_BADGE_PUNCH`）隐形；
  `img:` 图片徽章的纹理 quad 用 `COLOR_NAME` 作顶点色，alpha=0 → **整个图标消失**，
  只剩外面那圈不透明的等级环色，看起来就是"一个纯色圆点"。
  同一批常量里用于文字的（`COLOR_HEART` / `COLOR_HP_DIVIDER` / `COLOR_FACTION_DEFAULT`）
  靠 Font 兜底侥幸没暴露，但**不得依赖这个兜底**。
- **修复**：去掉全部 `& 0xFFFFFF`；`factionColor()` 解析 `#RRGGBB` 后主动补 `0xFF000000`。
  唯一允许 alpha≠0xFF 的是 `COLOR_LINE_BG`（`RpTheme.SHADOW`，刻意半透明底衬）。
- **如何失效（回归防线）**：`PlayerNametagRendererTest` 用反射遍历该类的 `COLOR_*` 常量并断言
  `alpha == 0xFF`（`COLOR_LINE_BG` 只要求可见）。**任何一次"顺手 & 0xFFFFFF"都会被这个用例挡下**——
  该用例在修复前是**失败**的（实测报 `COLOR_NAME 的 alpha=0`），修复后通过。
- **只管世界空间**：GUI 侧（`GuiGraphics.fill` / `RpIcons`）走的是 GUI 的混合状态，颜色本来就要带 alpha
  （`RpTheme.alphaBlend` 的淡入淡出就依赖它），所以那里**不要**套用本条规则、也不要反向去"补 alpha"。

## 6. 边界与注意（为什么 / 如何失效）

- **只改视觉**：布局 / 几何 / 行为 / 配置 / 网络 / 存档均不动，仅颜色与描边。
- **入场电影版式只有一种（2.25.3 起）**：信息固定在左下方、靠左对齐（标题 2.0x / 副标题 0.9x，图标居左、文字右移），
  旧的「完整版式」（屏幕中央居中、标题 3.4x / 副标题 1.4x）与其 per-faction 开关（阵营配置 `cinematicCompact`
  + 管理面板「简洁电影」按钮）已整体删除：同一画面留两套渲染路径，等于每次改版式都要同步两处，且没有真实使用方。
  **兼容边界**：存量 `factions.json` 里的 `cinematicCompact` 是孤儿键——不读、不写、结构保留（与 docs/16 §5 的
  `warheadEnabled` 同一处理方式），不需要迁移，也不会被表单保存清除；入场恒为下方版式（无论该键写 true 还是 false）。
  阵营配置 `cinematicBlackScreen`（管理面板「入场全屏黑」）不受影响，关闭后只保留文字/图标、不铺全屏黑。
- **如何失效**：若日后要恢复可切换版式，必须同时补齐四段——阵营字段（`FactionModels`/`FactionManager`）、
  客户端镜像投影（`CharacterService.buildSharedListRoot`）、部署载荷（`SpawnFramework` 的 CinematicS2C 装配）、
  面板开关（`RpAdminScreen` 阵营表单）；缺任何一段都会退化成「保存了却不生效」（docs/01 §11.2），并需在此登记版式契约。
- **脱离主题的风险**：若新增界面直接写彩色字面量而不走 `RpTheme`，会与黑白灰终端不一致。
  2.24.1 起 `com.ccnrcom.rp.client` 内裸色值已清零，新增样式必须走 §2.1 令牌与共享入口；
  代码评审的检查方法：`grep -rn "0x[0-9A-Fa-f]\{8\}" src/main/java/com/ccnrcom/rp/client/ | grep -v RpTheme.java`
  应只剩 `#RRGGBB` 解析用的 alpha 掩码。
- **刻意保留的彩色（仅两处，均为语义刚需）**：
  1. **红色警戒 / 危险**（`RED`/`RED_LINE`/`RED_DIM`/`RED_BG*`）——唯一保留的警示色。
  2. **关系语义蓝**（`FRIENDLY` = 0xFF4FA6FF，配 `NEUTRAL` 白 / `HOSTILE` 红）——关系图、关系页签、
     入场电影与击杀播报需要「友好/中立/敌对」三态可区分，红已被敌对占用，故保留蓝作为第三色；
     三处统一走 `RpTheme.relationColor()`，不得各自另取颜色（2.24.1 前击杀播报的「友好」曾用亮灰，属偏差，已修）。
  3. 另有 `STATUS_OBSERVING`（0xFF7E8A8F，观察态弱灰-青）为状态语义刻意保留的弱色。
- **白色选中可读性（硬约束）**：反白依赖 `selectedBar` 白色底 + 该行文字用 `ACCENT_TEXT`（深色）；
  任何「亮底/白底」填充（`selectedBar`、`ACCENT_FILL`、`popupRow(current=true)`、亮灰标签块）之上的文字
  **必须**用 `ACCENT_TEXT`，否则白底白字不可读。2.24.1 已修：K 面板部署确认「确认」按钮、职业列表
  `Lv x` / 在职上限标签、`StatusHud` 进度条百分比。
  新增同类构件时按此三条自检：①该填充是否为亮色；②文字是否深色；③深色文字是否只在亮底分支出现。
- **与前端一致性边界**：前端为 CSS 渲染，MC 为 int 色值、无渐变/阴影/抗锯齿，呈现为「同设计语言的近似值」，非逐像素相同。
- **颜色守护（2.24.1 起）**：`RpThemeTest` 把本节的契约变成可执行断言——①反射遍历 `RpTheme` 全部颜色令牌，
  凡非中性灰（R≠G≠B）必须在「刻意保留清单」内；②反白填充 + `ACCENT_TEXT` 的对比度 ≥ 4.5（WCAG AA）；
  ③浮层卡片比面板更不透明、内陷槽比卡片底更亮、列表悬停比常态亮、滚动条轨道按溢出分档；
  ④等级灰阶单调、关系三态两两不同且未知值回退中立；⑤`alphaBlend` 保 RGB 只改 alpha。
  新增/改色令牌若违反契约，`build -PrunTests` 直接红。渲染结果本身仍靠人工 review（无快照测试）。
- 一致性维护流程：改色后跑 `spotlessApply` + `build -PrunTests`（后者含颜色守护），并同步 §2.1 令牌表。
